# Markdown 写法完全指南（Obsidian 知识库专用）

> 本教程针对 Obsidian 知识库场景编写，涵盖基础语法 + Obsidian 扩展语法 + 知识库写作规范。
> 建议将此文件放入 `01-MOC/` 或 `99-Archive/` 作为速查手册。

---

## 一、为什么用 Markdown？

Markdown 是一种**轻量级标记语言**，用简单的符号就能排版，专注于内容而非格式。

| 对比         | Word      | Markdown    |
| ---------- | --------- | ----------- |
| 打开速度       | 慢，需要软件    | 快，任何文本编辑器   |
| 格式控制       | 鼠标点选，容易乱  | 符号标记，结构清晰   |
| 跨平台        | 依赖 Office | 到处都能打开      |
| 与 Obsidian | 无法兼容      | 原生支持，可双向链接  |
| 版本管理       | 难         | 配合 Git 完美追踪 |

**核心原则：用 Markdown 写内容，用 Obsidian 做连接。**

## 二、基础语法（10分钟掌握）

### 2.1 标题

用 `#` 表示标题，1-6个 `#` 对应1-6级标题。

```markdown
# 一级标题（通常用于笔记标题）
## 二级标题（模块/大章节）
### 三级标题（小节）
#### 四级标题（细分点）
##### 五级标题（很少用）
###### 六级标题（几乎不用）
```

**Obsidian 技巧：**
- 左侧大纲视图会根据标题自动生成目录
- 标题是笔记的「骨架」，建议任何笔记至少用到三级标题
- 一级标题 `#` 一个笔记只用一次（就是笔记名）

---

### 2.2 段落与换行

```markdown
这是第一段。直接回车不会换行，需要空一行才是新段落。

这是第二段。两段之间要有一个空行。
```

**注意：**
- Markdown 中按一次回车 = 同一段内换行（显示为空格）
- 按两次回车（中间空一行）= 新段落
- 如果想强制换行但不空行，在行尾加两个空格 `  ` 然后回车

---

### 2.3 文字样式

```markdown
**粗体**：两个星号包裹
*斜体*：一个星号包裹
***粗斜体***：三个星号包裹
~~删除线~~：两个波浪线包裹
==高亮==：两个等号包裹（Obsidian 支持）
`行内代码`：反引号包裹
```

**效果：**
- **粗体**：两个星号包裹
- *斜体*：一个星号包裹
- ***粗斜体***：三个星号包裹
- ~~删除线~~：两个波浪线包裹
- ==高亮==：两个等号包裹（Obsidian 支持）
- `行内代码`：反引号包裹

**写作规范：**
- 强调概念时用 **粗体**
- 引用术语或外文时用 *斜体*
- 标记过时内容用 ~~删除线~~
- 标记重点内容用 ==高亮==（Obsidian 特有）
- 代码、函数名、文件名用 `行内代码`

### 2.4 列表

#### 无序列表（ bullet points ）

```markdown
- 项目一
- 项目二
  - 子项目（前面加两个空格或一个Tab）
  - 子项目二
- 项目三
```

**效果：**
- 项目一
- 项目二
  - 子项目
  - 子项目二
- 项目三

**符号选择：**
- `-` 最常用，推荐统一
- `*` 也可以，但容易和斜体混淆
- `+` 也可以，但不常用

#### 有序列表

```markdown
1. 第一步
2. 第二步
3. 第三步
   1. 子步骤一
   2. 子步骤二
```

**效果：**
1. 第一步
2. 第二步
3. 第三步
   1. 子步骤一
   2. 子步骤二

**注意：**
- 数字后面跟英文句点 `.` 和一个空格
- 子列表缩进3个空格
- 实际显示的数字会按顺序排列，即使 Markdown 里写错数字

#### 任务列表（复选框）

```markdown
- [ ] 未完成的任务
- [x] 已完成的任务
- [ ] 另一个待办
```

**效果：**
- [ ] 未完成的任务
- [x] 已完成的任务
- [ ] 另一个待办

**Obsidian 技巧：**
- 点击复选框可以直接切换完成状态
- 配合 Daily Note 做每日待办非常好用
- 可以用 Dataview 查询所有未完成的任务

### 2.5 引用

```markdown
> 这是一段引用文字。
> 可以有多行。
>> 这是嵌套引用。
```

**效果：**
> 这是一段引用文字。
> 可以有多行。
>> 这是嵌套引用。

**使用场景：**
- 引用书籍、文章、他人观点
- 在笔记中标记「原文摘录」
- 写复盘时引用他人的反馈

### 2.6 分隔线

```markdown
---

***

___
```

三种写法效果一样，推荐用 `---`（三个减号），最直观。

**使用场景：**
- 分隔不同章节
- 在笔记末尾分隔「正文」和「参考资料」

### 2.7 链接

#### 外部链接（网址）


**效果：**

**效果：**

#### 代码块

用三个反引号包裹，并指定语言：

<pre>

```sql
    user_id,
```

</pre>

- 代码块会自动语法高亮
- 支持的语言：python、sql、javascript、markdown 等几十种

## 三、Obsidian 扩展语法

### 3.1 双向链接（WikiLink）

这是 Obsidian 的灵魂功能。

```markdown
[[目标笔记]]
[[目标笔记|自定义显示文字]]
[[目标笔记#标题]]
[[目标笔记#标题|自定义显示文字]]
[[目标笔记#^段落ID]]
```

**示例：**
```markdown
在 [[85-14 销售与商务拓展|达人建联岗位笔记]] 中，我整理了筛选指标。

具体筛选方法见 [[85-14 销售与商务拓展#核心能力一：达人筛选能力]]。
```

**使用原则：**
- 提到一个概念时，如果已有笔记，立刻链接
- 还没写的概念，用 `[[概念名]]` 创建占位链接，以后补
- 链接是知识库的「神经元连接」，链接越多，知识网越密

---

### 3.2 标签（Tags）

```markdown
#标签名
#S1-初学
#岗位-达人建联
#场景-面试
#2026-Q3
```

**Obsidian 技巧：**
- 点击标签可以查看所有带此标签的笔记
- 标签可以嵌套：`#岗位/达人建联`（Obsidian 支持层级标签）
- 建议统一标签体系，不要随心所欲创建

**你的知识库推荐标签：**
```markdown
#S1-初学 #S2-理解 #S3-掌握 #S4-精通
#输出-待复习 #输出-待实践 #输出-已内化

#来源-课程 #来源-书籍 #来源-实习
#岗位-咨询 #岗位-投行 #岗位-达人建联
#2026-Q3 #2026-Q4
```

## 四、知识库写作规范

### 4.1 笔记命名规范

| 场景 | 推荐格式 | 示例 |
|------|---------|------|
| 概念笔记 | `概念名` | `供需与弹性`、`窗口函数` |
| 岗位笔记 | `编号 岗位名` | `85-14 销售与商务拓展` |
| MOC 页 | `编号-模块名 MOC` | `20-数据与工具 MOC` |
| 项目复盘 | `日期 项目名` | `2026-07 贝恩杯复盘` |
| Daily Note | `YYYY-MM-DD` | `2026-08-01` |

**原则：**
- 不用特殊字符：`/ \ : * ? " < > |`
- 不用中文序号（如一、二、三），用阿拉伯数字
- 文件名即标题，看到文件名就知道内容

### 4.2 笔记结构模板

每篇笔记建议遵循以下结构：

```markdown
# 笔记标题

> 标签：#标签1 #标签2
> 来源：书籍/课程/实习/对话
> 日期：2026-08-01

---

## 一句话定义
（用自己的话，30字以内概括）

## 核心内容
（分章节展开）

### 子主题1
...

### 子主题2
...

## 我的理解
（费曼测试：尝试讲给不懂的人听）

## 关联笔记
- [[相关概念1]]
- [[相关概念2]]

## 待办/待补充
- [ ] 补充案例
- [ ] 链接到项目实践

## 参考来源
- 书籍：
- 文章：
- 课程：
```

### 4.3 链接规范

**应该链接的情况：**
- 提到一个已存在的概念笔记时
- 引用另一篇笔记的结论时
- 项目复盘关联到相关知识点时

**不应该链接的情况：**
- 普通词汇（如「今天」、「公司」）
- 一句话里出现多次同一个概念（只链第一次）
- 临时想法还没整理成笔记时（先写，后补链接）

### 4.4 标签使用规范

**DO：**
- 统一标签体系，写在笔记开头
- 用标签标记掌握程度：`#S1-初学` → `#S2-理解` → `#S3-掌握`
- 用标签标记场景：`#场景-面试`、`#场景-报告`

**DON'T：**
- 一篇笔记打10个标签（标签失去意义）
- 标签命名不统一（如 `#SQL` 和 `#sql` 会被视为两个标签）
- 用句子做标签（标签应该是分类词）

## 五、实战示例

### 示例1：概念笔记

```markdown
# 供需与弹性

> 标签：#经济学 #S1-初学 #10-1-经济学基础
> 来源：《经济学原理》曼昆
> 日期：2026-08-01

---

## 一句话定义
价格是供需关系的结果，弹性衡量的是「敏感程度」。

## 核心原理

### 需求定律
其他条件不变时，价格上涨 → 需求量下降。

例外情况（吉芬商品、炫耀性消费）→ [[吉芬商品]]

### 弹性分类

| 弹性类型 | 定义 | 例子 |
|---------|------|------|
| 需求价格弹性 | 需求量变化% / 价格变化% | 奢侈品弹性大，食盐弹性小 |
| 供给价格弹性 | 供给量变化% / 价格变化% | 农产品短期弹性小 |
| 收入弹性 | 需求量变化% / 收入变化% | 正常品>0，劣等品<0 |

### 弹性与定价策略
- 弹性大的商品（如化妆品）：降价能大幅提升销量
- 弹性小的商品（如药品）：涨价对销量影响小

## 我的理解
弹性就像「脾气」。脾气大的（弹性大），你一动TA就反应剧烈；
脾气小的（弹性小），你怎么动TA都淡定。

企业定价前，必须先摸清自己产品的「脾气」。

## 关联笔记
- [[边际效用递减]]
- [[价格歧视]]
- [[10-1 经济学基础 MOC]]

## 实践应用
- [[90-3 实习复盘/联邦制药]] 中分析药品定价时用到

## 参考来源
- 书籍：《经济学原理》曼昆，第4-5章
- 课程：南京大学 微观经济学
```

```markdown
## 核心能力模型

| 能力 | 权重 | 知识库映射 | 我的水平 |

| 达人筛选 | ★★★★★ | [[达人筛选能力]] | #S1-初学 |

## 面试高频问题

### Q1：你怎么筛选达人？
**框架**：黄金公式 + 定量指标 + 定性维度

**回答**：
"我筛选达人的逻辑是「先定量筛健康度，再定性看匹配度」。

定量层面，我会看四个核心指标：
1. 互动率：近10条视频的平均互动率，>5%是健康线
2. 粉互比：粉丝量与互动量的比例，<1:10比较健康
3. 粉丝增长趋势：近30天是否正增长
4. 带货转化率：>1.5%说明有带货能力

定性层面，我看三个维度：
1. 内容垂直度：垂类内容占比是否>70%
2. 调性匹配度：达人的风格是否与品牌气质一致
3. 人设真实性：评论区是否有真实用户提问

最后，我不会只盯着头部，而是按头部40%、中腰部35%、素人20%、KOC5%的预算分配策略来建联。"
```

## 八、自检清单

写完一篇笔记后，检查：

- [ ] 有一级标题（笔记标题）
- [ ] 有标签（至少1个）
- [ ] 有双向链接（至少1个）
- [ ] 有「一句话定义」或「核心摘要」
- [ ] 有「我的理解」或「费曼测试」段落
- [ ] 有「参考来源」
- [ ] 没有死链接（红色的 `[[链接]]`）
- [ ] 没有未闭合的格式符号（如只有一个 `*`）
