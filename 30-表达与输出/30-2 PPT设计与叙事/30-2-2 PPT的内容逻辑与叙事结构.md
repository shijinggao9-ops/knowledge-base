# 30-2-2 PPT的内容逻辑与叙事结构（金字塔结构、故事线、页面逻辑）

**定位**：PPT的视觉决定了“好不好看”，PPT的逻辑决定了“能不能让人听懂”。很多PPT的视觉并不差，但听众听完之后记不住核心观点——原因往往不在设计，而在于“没有结构”。这个文件回答三个核心问题：PPT的整体逻辑怎么组织？怎样让听众“跟得上、记得住”？每一页PPT应该怎么设计内容？理解这些，你就能从“把内容塞进PPT”升级到“用PPT讲一个逻辑清晰的故事”。

**适用场景**：任何需要制作PPT的场景——工作汇报、方案提案、面试展示、融资路演、数据分析报告。


## 一、核心概念词典


### 1.1 PPT逻辑的底层原则

PPT的逻辑结构遵循 **金字塔原理**（详见30-1-2）：结论先行，以上统下，归类分组，逻辑递进。

**金字塔原理在PPT中的对应关系**：

| 金字塔层次 | PPT中的对应 | 示例 |
|:-----------|:------------|:-----|
| **塔尖（核心结论）** | 封面 + 结论页 | “Q3销售额1.2亿，同比增长15%” |
| **中间（分论点）** | 各个板块的标题页/过渡页 | “驱动力一：华东地区增长22%” |
| **底部（支撑细节）** | 各页正文中的数据、图表、案例 | 图表展示各区域增长率 |

**听众的“三步认知”** ：

| 步骤 | 听众在想什么 | PPT需要提供什么 |
|:-----|:-------------|:----------------|
| 第一步 | “你要说什么？” | 核心结论（封面/开头） |
| 第二步 | “为什么？” | 分论点（结构清晰的正文） |
| 第三步 | “然后呢？” | 结论+行动建议（结尾） |


### 1.2 PPT的整体结构

一个完整的PPT通常由五部分组成：

| 部分 | 页数 | 功能 | 关键内容 |
|:-----|:----:|:-----|:---------|
| **封面** | 1页 | 建立第一印象，告诉听众“今天讲什么” | 标题=核心结论；演讲者信息 |
| **目录/概览** | 1页 | 给听众“地图”——今天要讲几个部分 | 3-5个板块标题 |
| **正文** | 8-30页 | 展开论述，支撑核心结论 | 每个板块对应一个分论点，用数据和案例支撑 |
| **结论/总结** | 1-2页 | 重申核心结论，给出行动建议 | 结论+下一步 |
| **附录** | 可选 | 放置补充信息（不展示，只在提问时调用） | 原始数据、详细资料 |


### 1.3 正文的三种逻辑结构

正文是PPT的主体，根据不同的表达目的，选择不同的逻辑结构。

#### 结构一：问题-方案-结果

**适用场景**：项目汇报、案例展示、提案陈述

| 阶段 | 内容 | 页数占比 |
|:-----|:-----|:--------:|
| **问题** | 当时遇到了什么挑战？ | 20% |
| **方案** | 我们做了什么？为什么这么做？ | 50% |
| **结果** | 最终效果如何？ | 30% |

**逻辑流程**：
> 背景 → 挑战/问题 → 我们的方案 → 执行过程 → 结果 → 经验/启示

#### 结构二：现状-分析-建议

**适用场景**：分析报告、战略提案、咨询汇报

| 阶段 | 内容 | 页数占比 |
|:-----|:-----|:--------:|
| **现状** | 现在是什么情况？ | 30% |
| **分析** | 为什么会出现这种情况？ | 40% |
| **建议** | 接下来应该怎么做？ | 30% |

**逻辑流程**：
> 现状描述 → 数据分析 → 根因诊断 → 解决方案 → 实施建议

#### 结构三：SCQA（情境-冲突-问题-答案）

**适用场景**：方案提案、融资路演、需要“吸引注意力”的汇报

| 阶段 | 内容 | 页数占比 |
|:-----|:-----|:--------:|
| **情境**（Situation）| 现在是什么情况？ | 10% |
| **冲突**（Complication）| 遇到了什么挑战？ | 25% |
| **问题**（Question）| 要解决的核心问题是什么？ | 10% |
| **答案**（Answer）| 我们的方案是什么？ | 55% |

**逻辑流程**：
> 背景（1-2页）→ 冲突（3-5页）→ 问题（1页）→ 答案（8-15页）→ 结论（1页）


### 1.4 PPT的故事线（Storyline）

故事线是把“逻辑结构”转化为“叙事节奏”的工具——它决定了听众在每一页“感受到什么”。

**故事线的三个要素**：

| 要素 | 定义 | PPT中的体现 |
|:-----|:-----|:------------|
| **开头吸引注意力** | 让听众产生好奇心 | SCQA中的“冲突”部分；或用一个有力的数据开篇 |
| **中间有逻辑递进** | 每一步都承接上一步 | 板块之间的过渡页；每页标题形成“连贯的句子” |
| **结尾有行动呼吁** | 让听众知道“接下来做什么” | 结论页+行动建议；明确的时间节点和责任分工 |

**故事线的“情感曲线”** ：

| 阶段 | 听众情绪 | PPT设计意图 |
|:-----|:---------|:------------|
| 开头 | 好奇/疑问 | “这个问题确实存在” |
| 中间（分析）| 认同/思考 | “原来原因是这个” |
| 中间（方案）| 期待/信任 | “这个方案能解决” |
| 结尾 | 行动/决心 | “我们就这样做” |

**检查故事线是否成立的方法**：把所有页面的标题连起来读一遍，看是否能形成一段流畅的“摘要”——如果能，故事线成立；如果不能，说明逻辑断链。


### 1.5 每一页PPT的内容逻辑

#### 页面标题 = 该页的核心结论

| ❌ 错误的标题写法 | ✅ 正确的标题写法 |
|:------------------|:------------------|
| “Q3销售数据” | “Q3销售额1.2亿，同比增长15%” |
| “用户反馈汇总” | “用户最关注的三个问题是：价格、功能、服务” |
| “竞品分析” | “竞品A在价格上领先，我们在功能上有优势” |
| “新功能上线” | “新功能上线后，用户转化率提升了12%” |
| “项目进展” | “项目按计划推进，预计8月30日上线” |

> **规则**：如果你把标题读出来，听众应该知道“这页PPT的核心观点是什么”——而不是“这页PPT的主题是什么”。

#### 每页内容的“三层信息结构”：

| 层级 | 内容 | 字号 | 视觉权重 |
|:-----|:-----|:----:|:--------:|
| **第一层：结论（标题）** | 这一页的核心观点 | 最大 | 最突出 |
| **第二层：支撑** | 支撑结论的2-4个要点 | 中等 | 次突出 |
| **第三层：细节** | 数据、图表、案例的细节 | 较小 | 辅助 |

**页面内容的“减法原则”** ：

| 检查项 | 标准 |
|:-------|:-----|
| 这一页是否只有一个核心观点？ | 如果是，保留；如果有两个，拆分到两页 |
| 这一页的内容是否直接支撑标题？ | 如果是，保留；如果不是，删除或修改 |
| 这一页是否可以用一句话总结？ | 如果可以，说明清晰；如果不可以，需要简化 |


### 1.6 板块之间的过渡页

过渡页的作用是让听众知道“我们正在进入下一个部分”——它是逻辑结构的“路标”。

**过渡页的标准结构**：

| 要素 | 内容 | 示例 |
|:-----|:-----|:-----|
| 大数字/大标题 | 当前部分的编号和标题 | “第二部分” |
| 一句话说明 | 这个部分要讲什么 | “从数据到洞察：客户流失原因分析” |
| 进度指示 | 告诉听众“我们已经讲了什么、还剩什么”| “第一部分 · 第二部分 · 第三部分” |

**过渡页的使用原则**：
- 3-5个板块的PPT，每个板块前加1页过渡页
- 过渡页要简洁（2-4个元素），让听众的注意力聚焦在“接下来要讲什么”


### 1.7 不同类型PPT的结构差异

#### 汇报型PPT（进展汇报、周报/月报）

| 建议结构 | 页数 |
|:---------|:----:|
| 封面 | 1 |
| 核心结论（一句话总结）| 1 |
| 关键数据（3-5个核心指标）| 1-2 |
| 进展详情（按板块展开）| 3-8 |
| 问题与风险 | 1-2 |
| 下一步计划 | 1 |
| 需要支持/决策的事项 | 1 |

#### 方案提案型PPT

| 建议结构 | 页数 |
|:---------|:----:|
| 封面 | 1 |
| 背景（S）| 1-2 |
| 冲突（C）| 2-3 |
| 问题（Q）| 1 |
| 方案概述（A）| 1 |
| 方案详情（按模块展开）| 4-10 |
| 预期效果/ROI | 1-2 |
| 实施计划 | 1 |
| 预算/资源需求 | 1 |
| 结论与行动 | 1 |

#### 融资路演PPT（一般10-15页）

| 建议结构 | 页数 |
|:---------|:----:|
| 封面（一句话定位）| 1 |
| 问题（用户痛点）| 1-2 |
| 方案（产品/服务）| 1-2 |
| 市场机会（TAM/SAM/SOM）| 1-2 |
| 商业模式 | 1 |
| 竞争优势（护城河）| 1 |
| 关键数据（里程碑）| 1 |
| 团队 | 1 |
| 融资需求与用途 | 1-2 |

#### 面试展示PPT（案例分析/作品集）

| 建议结构 | 页数 |
|:---------|:----:|
| 封面（核心结论）| 1 |
| 背景与目标 | 1 |
| 分析过程 | 2-4 |
| 关键发现 | 2-3 |
| 解决方案 | 1-2 |
| 预期效果 | 1 |
| 总结与收获 | 1 |


## 二、商业场景还原


### 场景1：从“数据堆砌”到“逻辑递进”

**原始PPT的问题**：10页全是数据图表，没有标题，没有结论，听众不知道“这些数据说明了什么”。

**改造后的逻辑结构**：

| 页码 | 标题 | 内容 |
|:-----|:-----|:-----|
| 1 | 封面：Q3销售额1.2亿，同比增长15% | 核心结论 |
| 2 | 目录：①整体表现 ②区域分析 ③产品分析 ④下一步计划 | 概览 |
| 3 | 整体表现：Q3达成目标的103% | 核心数据 |
| 4 | 区域分析：华东是主要增长引擎 | 图表 |
| 5 | 区域分析：华南增长放缓，需关注 | 图表 |
| 6 | 产品分析：A产品贡献60%的营收 | 图表 |
| 7 | 产品分析：B产品增速最快（+45%）| 图表 |
| 8 | 下一步：优化华南渠道，加大B产品投入 | 行动建议 |


### 场景2：SCQA故事线在提案中的应用

**场景**：向老板提案“建立客户成功团队”

**故事线**：

| 页码 | 标题 | 故事角色 |
|:-----|:-----|:---------|
| 1 | 客户续费率持续下滑，从75%降至68%（冲突） | 吸引注意力 |
| 2 | 我们目前只有被动客服，缺乏主动客户运营（情境）| 建立背景 |
| 3 | 流失客户中，80%是因为“无人主动跟进”（分析）| 加深冲突 |
| 4 | 核心问题：如何在不增加销售成本的情况下提升续费？（问题）| 引导思考 |
| 5 | 建议：组建客户成功团队（答案）| 给出方案 |
| 6-10 | 客户成功团队的职责、成本、预期效果（展开）| 支撑方案 |
| 11 | 6个月内将续费率从68%提升到80%（结论）| 承诺结果 |


## 三、面试/实战中怎么用

### 3.1 面试中的PPT展示逻辑

| 展示类型 | 逻辑结构 | 关键要点 |
|:---------|:---------|:---------|
| 自我介绍 | 结论先行（3个关键词概括自己）→ 展开 → 总结 | 10页以内，每页一个能力点 |
| 案例分析 | 问题→分析→方案→效果（STAR的PPT版）| 分析过程要清晰，方案要有数据支撑 |
| 作品集 | 背景→目标→我的角色→行动→结果→反思 | “我做了什么”+“效果如何” |

### 3.2 面试官看PPT时的“阅读顺序”

面试官在极短的时间内，通过三个层次判断你的PPT能力和思维质量：

| 层次 | 考察内容 | 时间 |
|:-----|:---------|:----:|
| **第一层：整体结构** | 有没有清晰的逻辑主线？结构是否合理？ | 10秒 |
| **第二层：单页内容** | 每页有没有核心结论？标题是否有力？ | 5秒/页 |
| **第三层：视觉细节** | 是否清晰？配色、字体、排版是否专业？ | 2秒/页 |

> 这意味着：**整体逻辑是最重要的**。视觉再漂亮，结构混乱也是失败的PPT。


## 四、常见误区

| 误区 | 真相 |
|:-----|:-----|
| “PPT的结构就是把内容按顺序排列” | ❌ 好的结构不是“内容的顺序”，而是“听众理解的路径”——你要主动设计听众的认知顺序 |
| “每页都要放尽量多的信息，节省页数” | ❌ 信息密度高=理解成本高。宁可多一页，也不要让一页挤满内容 |
| “目录页不重要，听众不会认真看” | ❌ 目录决定了听众的“认知地图”——没有地图的旅程，听众会迷路 |
| “标题就是这一页的主题” | ❌ 标题应该是这一页的**结论**，不是主题。主题是“销售数据”，结论是“销售增长了15%” |
| “SCQA只适合提案，不适合汇报” | ❌ SCQA的变体（如CSA）适用于所有需要“引起注意”的场景——包括汇报中的“问题页面”|


## 五、实战自测题

- [ ] **结构设计**：你需要在10分钟内做一个“用户增长项目复盘”的PPT，包含：背景、问题、行动、结果、反思。请列出每页的标题和关键内容（建议页数：10-12页）。

- [ ] **标题改写**：请将以下PPT主题改写为结论式标题：
  - （1）“市场趋势分析”
  - （2）“竞品对比”
  - （3）“用户需求调研”
  - （4）“成本结构优化方案”

- [ ] **故事线练习**：用SCQA结构设计一个“建议公司开通企业微信”的PPT故事线，列出每页的标题（建议页数：8-10页）。

- [ ] **逻辑诊断**：你收到一份PPT，其结构如下：封面→数据展示→数据展示→数据展示→数据展示→数据展示→结论。请诊断这个结构的问题，并提出改进建议。
