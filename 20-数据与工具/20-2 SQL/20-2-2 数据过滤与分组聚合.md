# 20-2-2 数据过滤与分组聚合（GROUP BY、HAVING、CASE WHEN）

**定位**：分组聚合是SQL从“取数工具”升级为“分析工具”的分水岭——没有分组聚合，SQL只能做“查数据”；有了分组聚合，SQL能做“看趋势、比差异、算汇总”。`GROUP BY`让你按任意维度汇总数据（如“每个城市的销售额”），`HAVING`让你筛选汇总后的结果（如“只显示销售额超过100万的城市”），`CASE WHEN`让你在SQL中实现条件判断和逻辑分支（如“把金额分成高/中/低三档”）。掌握这些，你就能独立完成从“原始数据”到“分析结论”的全过程。

**适用场景**：按维度汇总业务数据（销售日报/周报）、计算占比和分布、数据分层与打标、面试中的SQL分组聚合题目。


## 一、核心概念词典

### 1.1 聚合函数（Aggregate Functions）

聚合函数对一组值执行计算并返回**单个汇总值**。它们是分组分析的基础工具。

| 函数 | 用途 | 示例 | 返回值 |
|:-----|:-----|:-----|:--------|
| `COUNT(*)` | 统计总行数（包含NULL）| `COUNT(*)` | 所有记录数 |
| `COUNT(列名)` | 统计该列非空值的个数 | `COUNT(email)` | 有邮箱的客户数 |
| `COUNT(DISTINCT 列名)` | 统计该列不同值的个数（去重计数）| `COUNT(DISTINCT city)` | 有多少个不同城市 |
| `SUM(列名)` | 对数值列求和 | `SUM(amount)` | 总销售额 |
| `AVG(列名)` | 对数值列求平均值 | `AVG(amount)` | 平均客单价 |
| `MAX(列名)` | 返回最大值 | `MAX(price)` | 最高单价 |
| `MIN(列名)` | 返回最小值 | `MIN(price)` | 最低单价 |

**示例**：

```sql
SELECT
  COUNT(*) AS 总订单数,
  SUM(amount) AS 总销售额,
  AVG(amount) AS 平均客单价,
  MAX(amount) AS 最大单笔订单,
  MIN(amount) AS 最小单笔订单
FROM orders;
```
**关于COUNT的常见陷阱**：
```sql
-- 统计所有行（包括NULL）
SELECT COUNT(*) FROM orders;        -- 返回所有订单数

-- 统计某列非空值（NULL不计入）
SELECT COUNT(customer_id) FROM orders;  -- 如果customer_id有NULL，结果会小于COUNT(*)

-- 去重计数（最常见的业务场景：统计不同客户数量）
SELECT COUNT(DISTINCT customer_id) FROM orders;  -- 统计有多少个不同的客户下了单
```
### 1.2 GROUP BY：按维度分组汇总

`GROUP BY`将数据按指定列分组，然后对每个组分别应用聚合函数。

**语法**：

```sql
SELECT 分组列, 聚合函数(聚合列)
FROM 表名
WHERE 过滤条件
GROUP BY 分组列;
```

**执行逻辑**：

1. `FROM` → 确定数据来源
    
2. `WHERE` → 行级过滤
    
3. `GROUP BY` → 将数据分成若干组
    
4. `SELECT` → 对每组执行聚合函数，返回汇总结果
    

**示例**：按城市汇总销售额

```sql
SELECT
  city,
  SUM(amount) AS 总销售额,
  COUNT(*) AS 订单数,
  AVG(amount) AS 平均客单价
FROM orders
WHERE order_date >= '2026-01-01'
GROUP BY city;
```

**输出**：

|city|总销售额|订单数|平均客单价|
|---|---|---|---|
|北京|1,250,000|500|2,500|
|上海|980,000|420|2,333|
|深圳|720,000|300|2,400|

#### 多列分组

按多个维度分组——如“按城市+产品类别”汇总。

```sql
SELECT
  city,
  category,
  SUM(amount) AS 销售额
FROM orders
GROUP BY city, category
ORDER BY city, category;
```

**输出**：

|city|category|销售额|
|---|---|---|
|北京|电子产品|500,000|
|北京|服装|300,000|
|北京|食品|450,000|
|上海|电子产品|400,000|

#### GROUP BY的重要规则

|规则|说明|正确/错误示例|
|---|---|---|
|`SELECT`中的非聚合列**必须**出现在`GROUP BY`中|如果某列不在`GROUP BY`中，又没有用聚合函数包裹，数据库不知道应该显示该组中的哪一行|❌ `SELECT city, name, SUM(amount) ... GROUP BY city`（name不在GROUP BY中，且非聚合）✅ `SELECT city, COUNT(*) ... GROUP BY city`|
|`GROUP BY`中的列不必出现在`SELECT`中|可以按某列分组但不显示该列|✅ `SELECT COUNT(*) ... GROUP BY city`（按城市分组，但只显示总订单数）|
|分组列可以有多个|多列组合成一个分组键|✅ `GROUP BY city, category`|

### 1.3 HAVING：过滤分组后的结果

`HAVING`用于对`GROUP BY`之后的结果进行过滤——它与`WHERE`的区别是：`WHERE`在分组前过滤行，`HAVING`在分组后过滤组。

**语法**：

```sql

SELECT 分组列, 聚合函数(聚合列)
FROM 表名
WHERE 行级过滤条件
GROUP BY 分组列
HAVING 组级过滤条件;

**`WHERE` vs `HAVING`的核心区别**：

|维度|WHERE|HAVING|
|---|---|---|
|执行时机|在`GROUP BY`**之前**|在`GROUP BY`**之后**|
|过滤对象|原始行（记录级别）|分组后的组（汇总级别）|
|能否使用聚合函数|❌ 不能|✅ 可以（如`SUM() > 1000`）|
|能否使用列别名|❌ 不能（别名在SELECT阶段才产生）|✅ 可以（某些数据库，如MySQL）|
```

**示例**：只显示总销售额超过100万的城市

```sql
SELECT
  city,
  SUM(amount) AS total_sales
FROM orders
WHERE order_date >= '2026-01-01'
GROUP BY city
HAVING SUM(amount) > 1000000   -- 只保留销售额>100万的城市
ORDER BY total_sales DESC;
```

**等效理解**：

1. `WHERE`先过滤掉2026年之前的订单（行级过滤）
    
2. `GROUP BY`按城市分组，计算每个城市的`SUM(amount)`
    
3. `HAVING`只保留`SUM(amount) > 1000000`的城市（组级过滤）
    
4. `ORDER BY`按总销售额降序排列
    

**HAVING的常见用法**：

```sql

-- ① 过滤分组后的聚合结果
HAVING COUNT(*) >= 10           -- 只保留订单数≥10的组
HAVING AVG(amount) > 500        -- 只保留平均客单价>500的组
-- ② 过滤分组后的统计指标
HAVING MAX(amount) - MIN(amount) > 1000  -- 组内金额极差>1000
-- ③ 结合多个条件
HAVING COUNT(*) >= 10 AND SUM(amount) > 100000
```

### 1.4 CASE WHEN：SQL中的条件判断

`CASE WHEN`是SQL中的`IF`语句——它允许你在查询中根据条件返回不同的值。

**两种语法**：

**语法一：简单CASE（等值判断）**

```sql
CASE 列名
  WHEN 值1 THEN 结果1
  WHEN 值2 THEN 结果2
  ELSE 默认结果
END
```

**语法二：搜索CASE（条件判断，更灵活）**

```sql

CASE
  WHEN 条件1 THEN 结果1
  WHEN 条件2 THEN 结果2
  ELSE 默认结果
END
```

**示例**：将金额分为“高/中/低”三档

```sql

SELECT
  order_id,
  amount,
  CASE
    WHEN amount >= 10000 THEN '高额订单'
    WHEN amount >= 5000 THEN '中额订单'
    WHEN amount >= 1000 THEN '低额订单'
    ELSE '小额订单'
  END AS order_level
FROM orders;
```
**输出**：

|order_id|amount|order_level|
|---|---|---|
|1001|15,000|高额订单|
|1002|6,500|中额订单|
|1003|2,000|低额订单|
|1004|500|小额订单|

#### CASE WHEN在分组聚合中的应用

`CASE WHEN`配合`GROUP BY`可以实现“按自定义分组汇总”——这是数据分析中最强大的组合之一。

**示例**：按“订单等级”统计数量和金额

```sql

SELECT
  CASE
    WHEN amount >= 10000 THEN '高额订单'
    WHEN amount >= 5000 THEN '中额订单'
    ELSE '普通订单'
  END AS order_level,
  COUNT(*) AS 订单数,
  SUM(amount) AS 总金额,
  AVG(amount) AS 平均金额
FROM orders
GROUP BY
  CASE
    WHEN amount >= 10000 THEN '高额订单'
    WHEN amount >= 5000 THEN '中额订单'
    ELSE '普通订单'
  END
ORDER BY 平均金额 DESC;
```

**示例**：按年龄段分组统计用户数

```sql

SELECT
  CASE
    WHEN age < 18 THEN '未成年'
    WHEN age BETWEEN 18 AND 30 THEN '青年'
    WHEN age BETWEEN 31 AND 50 THEN '中年'
    ELSE '老年'
  END AS age_group,
  COUNT(*) AS user_count
FROM users
GROUP BY
  CASE
    WHEN age < 18 THEN '未成年'
    WHEN age BETWEEN 18 AND 30 THEN '青年'
    WHEN age BETWEEN 31 AND 50 THEN '中年'
    ELSE '老年'
  END
ORDER BY user_count DESC;
```

#### CASE WHEN的常见陷阱

|陷阱|说明|正确做法|
|---|---|---|
|条件顺序错误|`CASE WHEN amount >= 5000 THEN '中' WHEN amount >= 10000 THEN '高'`|条件从上到下匹配，一旦匹配成功就不再继续。**高额条件应该放在前面**|
|忘记处理ELSE|未匹配到的值返回NULL，可能导致后续计算异常|除非明确需要NULL，否则尽量加上`ELSE`，或使用`COALESCE`处理NULL|
|在`GROUP BY`中重复写CASE|在`SELECT`和`GROUP BY`中重复写CASE WHEN|某些数据库（如PostgreSQL）支持在`GROUP BY`中使用别名，可以简化写法|

### 1.5 分组聚合的综合示例

**场景**：分析2026年各城市的订单分布，要求：

- 按城市汇总订单数、总销售额、平均客单价
    
- 筛选出订单数≥100的城市
    
- 按总销售额降序排列
    
- 添加“销售等级”列
    

```sql

SELECT
  city,
  COUNT(*) AS order_count,
  SUM(amount) AS total_sales,
  AVG(amount) AS avg_order_value,
  CASE
    WHEN SUM(amount) >= 1000000 THEN 'A级'
    WHEN SUM(amount) >= 500000 THEN 'B级'
    ELSE 'C级'
  END AS sales_level
FROM orders
WHERE order_date BETWEEN '2026-01-01' AND '2026-12-31'
  AND city IS NOT NULL
GROUP BY city
HAVING COUNT(*) >= 100
ORDER BY total_sales DESC;
```

**关键要点**：

1. `WHERE`先过滤日期和空值（行级过滤）
    
2. `GROUP BY city`按城市分组
    
3. `COUNT(*)`、`SUM(amount)`、`AVG(amount)`计算每个城市的汇总指标
    
4. `CASE WHEN`基于`SUM(amount)`计算销售等级
    
5. `HAVING COUNT(*) >= 100`筛选出订单数≥100的城市
    
6. `ORDER BY total_sales DESC`排序
    

## 二、商业场景还原

> 本节将分组聚合还原到真实的商业情境中。

### 场景1：销售日报（按日期+产品汇总）

**情境**：每天需要生成一份销售日报，按产品和日期汇总销售额和订单量。

```sql

SELECT
  DATE(order_date) AS sale_date,
  product_name,
  COUNT(*) AS order_count,
  SUM(amount) AS total_sales
FROM orders
WHERE order_date >= CURRENT_DATE - INTERVAL 7 DAY   -- 最近7天
GROUP BY DATE(order_date), product_name
ORDER BY sale_date DESC, total_sales DESC;
```

### 场景2：客户分层分析（RFM简化版）

**情境**：市场部需要识别“高价值客户”（消费频次高、金额大）。

```sql

SELECT
  customer_id,
  COUNT(*) AS order_count,
  SUM(amount) AS total_spent,
  AVG(amount) AS avg_order_value,
  MAX(order_date) AS last_order_date,
  CASE
    WHEN COUNT(*) >= 10 AND SUM(amount) >= 50000 THEN 'VIP'
    WHEN COUNT(*) >= 5 AND SUM(amount) >= 10000 THEN '高价值'
    WHEN COUNT(*) >= 1 THEN '普通'
    ELSE '待激活'
  END AS customer_tier
FROM orders
WHERE order_date >= '2026-01-01'
GROUP BY customer_id
ORDER BY total_spent DESC;
```

### 场景3：找出“异常高”的销售员

**情境**：销售总监怀疑某个销售员有异常交易行为——他的平均客单价远高于团队均值。

```sql

SELECT
  salesperson,
  COUNT(*) AS order_count,
  AVG(amount) AS avg_order_value,
  MAX(amount) AS max_order,
  MIN(amount) AS min_order
FROM orders
WHERE order_date BETWEEN '2026-01-01' AND '2026-06-30'
GROUP BY salesperson
HAVING AVG(amount) > 10000   -- 平均客单价>1万
   AND COUNT(*) >= 10;       -- 至少有10笔订单（排除样本太小的情况）
```

### 场景4：分类汇总——各品类在不同渠道的表现

```sql

SELECT
  category,
  channel,
  COUNT(*) AS orders,
  SUM(amount) AS sales,
  AVG(amount) AS avg_order,
  ROUND(SUM(amount) * 100.0 / SUM(SUM(amount)) OVER(), 2) AS sales_pct  -- 各品类销售额占比（窗口函数）
FROM orders
WHERE order_date >= '2026-01-01'
GROUP BY category, channel
ORDER BY category, sales DESC;
```

## 三、面试/实战中怎么用

### 3.1 面试高频题

**题目1：“查询每个部门的员工人数和平均工资”**

```sql

SELECT
  department,
  COUNT(*) AS employee_count,
  AVG(salary) AS avg_salary
FROM employees
GROUP BY department;
```

**题目2：“查询订单数超过10笔的客户，显示客户ID和订单数”**

```sql

SELECT
  customer_id,
  COUNT(*) AS order_count
FROM orders
GROUP BY customer_id
HAVING COUNT(*) > 10;
```

**题目3：“查询每个城市的订单总金额，并按照总金额从高到低排序，只显示前5名”**

```sql

SELECT
  city,
  SUM(amount) AS total_sales
FROM orders
GROUP BY city
ORDER BY total_sales DESC
LIMIT 5;
```

**题目4：“将用户按年龄分组（未成年/青年/中年/老年），统计各组的用户数”**

```sql

SELECT
  CASE
    WHEN age < 18 THEN '未成年'
    WHEN age BETWEEN 18 AND 30 THEN '青年'
    WHEN age BETWEEN 31 AND 50 THEN '中年'
    ELSE '老年'
  END AS age_group,
  COUNT(*) AS user_count
FROM users
GROUP BY
  CASE
    WHEN age < 18 THEN '未成年'
    WHEN age BETWEEN 18 AND 30 THEN '青年'
    WHEN age BETWEEN 31 AND 50 THEN '中年'
    ELSE '老年'
  END
ORDER BY user_count DESC;
```
### 3.2 分组聚合的“避坑指南”

|问题|错误写法|正确写法|
|---|---|---|
|`SELECT`列不在`GROUP BY`中|`SELECT city, name, SUM(amount) ... GROUP BY city`|要么把`name`加入`GROUP BY`，要么用聚合函数包裹：`MAX(name)`|
|在`WHERE`中使用聚合函数|`WHERE SUM(amount) > 1000 ... GROUP BY city`|`WHERE`在`GROUP BY`之前执行，不能使用聚合函数。应放在`HAVING`中|
|`CASE WHEN`条件顺序错误|`WHEN amount >= 5000 THEN '中' WHEN amount >= 10000 THEN '高'`|高额条件放在前面：`WHEN amount >= 10000 THEN '高' WHEN amount >= 5000 THEN '中'`|
|`GROUP BY`中使用别名|`GROUP BY age_group`（某些数据库不支持）|MySQL支持，但标准SQL不支持。稳妥做法是直接写`CASE WHEN`表达式|

## 四、常见误区

|误区|真相|
|---|---|
|“`GROUP BY`和`ORDER BY`是一样的”|❌ `GROUP BY`用于**分组汇总**（将数据聚合），`ORDER BY`用于**排序**（改变数据的显示顺序）。两者功能完全不同|
|“`COUNT(*)`和`COUNT(列名)`结果总是一样的”|❌ `COUNT(*)`统计所有行（包含NULL），`COUNT(列名)`只统计该列非空的行。如果列中有NULL值，两者结果不同|
|“`HAVING`中的条件和`WHERE`中的条件可以互换”|❌ `WHERE`在分组前过滤，`HAVING`在分组后过滤。如果想过滤“行”（如`city = '北京'`）用`WHERE`；如果想过滤“组”（如`SUM(amount) > 1000`）用`HAVING`|
|“`CASE WHEN`只能在`SELECT`中使用”|❌ `CASE WHEN`可以在`SELECT`、`WHERE`、`GROUP BY`、`ORDER BY`中任意位置使用——它是SQL中的通用条件表达式|
|“分组后就不能看到原始数据了”|❌ 分组聚合的结果是汇总数据。但通过窗口函数（如`SUM() OVER()`），可以在保留原始行的同时显示汇总值——见20-2-4章节|
