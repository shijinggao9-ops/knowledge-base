**定位**：SQL是数据领域的“通用语言”——无论使用MySQL、PostgreSQL、SQL Server还是BigQuery，核心语法都是相通的。这个文件是SQL学习的起点，覆盖从“数据库是什么”到“从一张表中精确取出所需数据”的全过程。掌握这些基础，你就能完成工作中80%的简单取数需求：查客户信息、看订单记录、做基础筛选。更重要的是，这个文件为你建立正确的SQL思维框架——查询是“声明式”的（告诉数据库你要什么），而非“过程式”的（告诉数据库怎么做）。

**适用场景**：从数据库提取业务数据、面试中的SQL入门题、产品/运营/分析岗位的基础取数需求、自助BI工具（如Power BI/Tableau）中的原生查询。


## 一、核心概念词典

### 1.1 什么是SQL？为什么需要它？

**SQL（Structured Query Language，结构化查询语言）** 是一种用于管理和操作关系型数据库的标准化语言。

**为什么需要SQL？**

| 场景 | Excel能处理吗？ | SQL能处理吗？ |
|:-----|:---------------:|:-------------:|
| 数据量 > 10万行 | ❌ 卡顿或崩溃 | ✅ 轻松处理亿级数据 |
| 数据存储在服务器上 | ❌ 需要导出文件 | ✅ 直接在服务器查询 |
| 多张表关联查询 | ❌ 需手动VLOOKUP | ✅ 一条JOIN搞定 |
| 需要定期自动取数 | ❌ 手动重复操作 | ✅ 脚本自动化 |
| 多用户同时访问 | ❌ 容易版本冲突 | ✅ 数据库自带并发控制 |

**核心思维转换**：

| Excel思维 | SQL思维 |
|:----------|:--------|
| 看到的是全量数据 | 看到的是“查询结果”（数据库中的数据是不变的）|
| 操作是“点击+拖拽” | 操作是“写指令” |
| 数据存储在本地文件 | 数据存储在远程服务器 |
| 公式写在单元格里 | 查询写在编辑器里 |


### 1.2 关系型数据库的核心概念

在写SQL之前，先理解数据在数据库中是如何组织的。

| 概念                  | 类比Excel | 定义                 |
| :------------------ | :------ | :----------------- |
| **数据库（Database）**   | 整个工作簿   | 多个数据表的集合           |
| **表（Table）**        | 一个工作表   | 二维结构，有行有列          |
| **列（Column）**       | 一列      | 数据的一个字段（如“姓名”）     |
| **行（Row）**          | 一行      | 一条完整的数据记录          |
| **字段（Field）**       | 单元格     | 某行某列交叉处的值          |
| **主键（Primary Key）** | 唯一ID列   | 唯一标识一条记录的列（如“订单号”） |

**示例**：一张“客户表”可能是这样：

| customer_id（主键）| name | city | signup_date |
|:------------------:|:-----|:-----|:-------------|
| 1001 | 张三 | 北京 | 2025-01-15 |
| 1002 | 李四 | 上海 | 2025-02-20 |

### 1.3 SQL的基本结构（CRUD概览）

SQL的操作分为四大类，但数据分析中最核心、最常用的是`SELECT`查询。

| 操作类型 | 关键字 | 用途 | 数据分析使用频率 |
|:---------|:-------|:-----|:----------------:|
| **查询（Read）** | `SELECT` | 从表中提取数据 | ⭐⭐⭐⭐⭐（几乎全用到）|
| 添加（Create）| `INSERT` | 向表中插入新数据 | ⭐⭐ |
| 修改（Update）| `UPDATE` | 修改表中的数据 | ⭐⭐ |
| 删除（Delete）| `DELETE` | 删除表中的数据 | ⭐ |

> 对于数据分析/产品/运营岗位，只需要精通`SELECT`查询即可，`INSERT/UPDATE/DELETE`了解即可（这些通常由开发或DBA负责）。

### 1.4 第一个查询：SELECT 和 FROM

#### SELECT

用于指定你想查看的列。

```sql
-- 查看所有列
SELECT * FROM 表名;

-- 查看指定列
SELECT 列名1, 列名2 FROM 表名;

-- 给列起别名（AS可以省略）
SELECT 列名1 AS 别名1, 列名2 别名2 FROM 表名;```
```

**示例**：

```SQL 
-- 查看customers表的所有数据
SELECT * FROM customers;

-- 只查看姓名和城市
SELECT name, city FROM customers;

-- 使用别名，让列名更易读（中文别名需加引号）
SELECT name AS 客户姓名, city AS 所在城市 FROM customers;```
```
#### DISTINCT（去重）

去掉重复行，只显示唯一值。

```sql

-- 查看city列有哪些不重复的值
SELECT DISTINCT city FROM customers;
-- 查看不同城市-行业组合（去重组合）
SELECT DISTINCT city, industry FROM customers;```
```


#### LIMIT（限制返回行数）

限制查询返回的记录数量——在探索数据时非常有用，避免一次性返回百万行数据。

```sql

-- 只返回前5条记录
SELECT * FROM customers LIMIT 5;
-- 分页：跳过前10条，返回接下来的5条（常用于分页查询）
SELECT * FROM customers LIMIT 5 OFFSET 10;
```

- `LIMIT 5`：取5条
    
- `OFFSET 10`：从第11条开始取（跳过10条）
    

> **注意**：不同数据库的写法略有不同——MySQL用`LIMIT`，SQL Server用`TOP`，Oracle用`ROWNUM`。这里以最通用的MySQL/PostgreSQL语法为准。

### 1.5 数据过滤：WHERE

`WHERE`用于筛选符合条件的行——只在满足条件的记录上做运算，这是SQL中最常用的过滤工具。

```sql
SELECT 列名
FROM 表名
WHERE 条件;
```
#### 比较运算符

|运算符|含义|示例|
|---|---|---|
|`=`|等于|`WHERE city = '北京'`|
|`<>` 或 `!=`|不等于|`WHERE city <> '上海'`|
|`>`|大于|`WHERE age > 18`|
|`>=`|大于等于|`WHERE score >= 60`|
|`<`|小于|`WHERE amount < 1000`|
|`<=`|小于等于|`WHERE date <= '2026-01-01'`|

#### 逻辑运算符：AND、OR、NOT

组合多个条件：

```sql

-- AND：两个条件都要满足（取交集）
SELECT * FROM orders
WHERE amount > 1000 AND city = '北京';
-- OR：满足任意一个条件即可（取并集）
SELECT * FROM orders
WHERE amount > 10000 OR city = '北京';
-- NOT：取反
SELECT * FROM customers
WHERE NOT city = '北京';  -- 等价于 city != '北京'
```
#### IN 和 NOT IN

`IN`用于匹配多个值中的任意一个，比多个`OR`更简洁。

```sql

-- 等价于：WHERE city = '北京' OR city = '上海' OR city = '深圳'
SELECT * FROM customers
WHERE city IN ('北京', '上海', '深圳');
-- 排除这几个城市
SELECT * FROM customers
WHERE city NOT IN ('北京', '上海', '深圳');
```
#### BETWEEN

用于范围查询（包含边界值），常用于数字和日期。

```sql
-- 金额在1000到5000之间（包含1000和5000）
SELECT * FROM orders
WHERE amount BETWEEN 1000 AND 5000;
-- 日期在2026年1月1日到2026年6月30日之间
SELECT * FROM orders
WHERE order_date BETWEEN '2026-01-01' AND '2026-06-30';
```
#### LIKE（模糊匹配）

`LIKE`用于文本的**模糊匹配**，配合通配符使用，是处理字段中部分匹配或模式匹配的关键工具。

|通配符|含义|示例|匹配结果|
|---|---|---|---|
|`%`|任意长度（含0）的任意字符|`LIKE '张%'`|张三、张三四、张（“张”本身也算，因为%匹配0个字符）|
|`_`|单个任意字符|`LIKE '张_'`|张三、张四，但不匹配“张三四”（因为_只能匹配一个字符）|
|`[ ]`|字符集合中的任意一个|`LIKE '[张李]三'`|张三、李三|

> MySQL中默认`LIKE`是**不区分大小写**的，但具体取决于数据库的字符集和排序规则（Collation）。在PostgreSQL中`LIKE`默认区分大小写，如需忽略大小写可用`ILIKE`。

**示例**：

```sql

-- 查询姓名以“张”开头的客户
SELECT * FROM customers WHERE name LIKE '张%';
-- 查询邮箱后缀为“@company.com”的客户
SELECT * FROM customers WHERE email LIKE '%@company.com';
-- 查询手机号以“138”开头的客户（共11位，“_”用8个）
SELECT * FROM customers WHERE phone LIKE '138________';
```
#### IS NULL 和 IS NOT NULL

`NULL`在SQL中表示“缺失值”或“未知值”——它**不等于**空字符串`''`，也不等于0。

```sql
-- 查询email为空的客户
SELECT * FROM customers WHERE email IS NULL;
-- 查询有email地址的客户
SELECT * FROM customers WHERE email IS NOT NULL;
```
> **重要**：不能用 `= NULL` 或 `!= NULL` 来判断——在SQL中，`NULL`代表“未知”，与任何值的比较（即使是`NULL = NULL`）都会返回“未知”（UNKNOWN），而非TRUE或FALSE。必须使用`IS NULL`或`IS NOT NULL`。

### 1.6 排序：ORDER BY

对查询结果进行排序——务必放在`WHERE`之后、`LIMIT`之前。

```sql
SELECT 列名
FROM 表名
WHERE 条件
ORDER BY 排序列1 [ASC|DESC], 排序列2 [ASC|DESC];
```

| 关键字    | 含义       | 默认    |
| ------ | -------- | ----- |
| `ASC`  | 升序（从小到大） | ✅ 默认  |
| `DESC` | 降序（从大到小） | ❌ 需指定 |

**示例**：

```sql
-- 按金额从高到低排序（降序）
SELECT * FROM orders ORDER BY amount DESC;
-- 先按城市升序，同一城市内按金额降序
SELECT * FROM orders ORDER BY city ASC, amount DESC;
```
> 
> **重要**：`ORDER BY`可以使用`SELECT`子句中定义的别名，这是少数允许在`SELECT`之后引用别名的地方。这种特性因数据库而异，通常依赖别名时建议用`ORDER BY 1`（按第一列）或直接写原列名。
> 

### 1.7 SQL执行顺序（重中之重）

理解SQL各子句的**逻辑执行顺序**，是写出正确SQL、避免常见错误的核心基础。

> 注意：这是**逻辑执行顺序**（数据库优化器实际执行的顺序可能不同，但逻辑上按此顺序理解），用于帮助理解为何某些写法可行或不可行。

1. FROM        → 确定数据来源
2. WHERE       → 行级过滤（在分组前过滤）
3. GROUP BY    → 分组（第20-2-2章详述）
4. HAVING      → 分组后过滤（第20-2-2章详述）
5. SELECT      → 选择列、计算表达式、分配别名
6. ORDER BY    → 排序
7. LIMIT       → 限制返回行数

**为什么这个顺序很重要？**

|常见错误|原因|正确做法|
|---|---|---|
|`WHERE 别名 = '...'`|别名在`SELECT`阶段才产生，`WHERE`在`SELECT`之前执行，所以`WHERE`中**不能**使用`SELECT`中定义的别名|在`WHERE`中重复写原始表达式，或在`HAVING`中使用别名（但`HAVING`是在`GROUP BY`之后执行）|
|`ORDER BY 别名`|`ORDER BY`在`SELECT`之后执行，**可以使用**别名|✅ 合法|
|`WHERE`中用了聚合函数（如`SUM()`）|聚合函数在`GROUP BY`阶段执行，`WHERE`在此之前执行，所以`WHERE`中**不能**使用聚合函数|聚合函数的过滤应放在`HAVING`中|

**示例**：

```sql

-- ❌ 错误：WHERE中不能使用SELECT中定义的别名
SELECT name AS customer_name, city
FROM customers
WHERE customer_name = '张三';  -- 报错：customer_name不存在
-- ✅ 正确
SELECT name AS customer_name, city
FROM customers
WHERE name = '张三';
-- ✅ ORDER BY中可以使用别名
SELECT name AS customer_name
FROM customers
ORDER BY customer_name;  -- 正确
```

## 二、商业场景还原

> 本节将基础查询还原到真实的商业情境中。

### 场景1：提取特定条件的客户——用于营销活动

**情境**：市场部需要向“上海地区的活跃客户”发送促销邮件。活跃客户定义为“最近30天内有下单记录的客户”。

**第一步：查询“上海地区的客户”**

```sql
SELECT customer_id, name, email
FROM customers
WHERE city = '上海';
```

**第二步：查询“最近30天下过单的客户”（关联订单表，暂用子查询思想）**

```sql
SELECT DISTINCT customer_id
FROM orders
WHERE order_date >= CURRENT_DATE - INTERVAL 30 DAY;
```

**组合后（完整查询，用IN子查询—第20-2-3章节详述，此处先预览）** ：
```sql

SELECT customer_id, name, email
FROM customers
WHERE city = '上海'
  AND customer_id IN (
    SELECT DISTINCT customer_id
    FROM orders
    WHERE order_date >= CURRENT_DATE - INTERVAL 30 DAY
  );
```

**结果**：精确提取出目标客户清单，可直接导出用于邮件营销。

### 场景2：业务数据快速探查

**情境**：刚接入一张“订单表”，你不了解这张表有多少数据、有哪些字段、数据质量如何。

**探查步骤**：

```sql

-- ① 查看表结构（不同数据库命令不同，MySQL用DESCRIBE）
DESCRIBE orders;
-- ② 看前10条数据长什么样
SELECT * FROM orders LIMIT 10;
-- ③ 检查有多少条记录
SELECT COUNT(*) FROM orders;
-- ④ 查看订单日期的最小值和最大值（判断数据范围）
SELECT MIN(order_date), MAX(order_date) FROM orders;
-- ⑤ 查看有多少个不重复的客户ID
SELECT COUNT(DISTINCT customer_id) FROM orders;
```

### 场景3：查找“异常数据”

**情境**：财务部发现部分订单金额异常，想排查是否有负值、缺失值或极端高值。

```sql

-- ① 检查是否有空值（缺失）
SELECT * FROM orders WHERE amount IS NULL;
-- ② 检查是否有负值订单
SELECT * FROM orders WHERE amount < 0;
-- ③ 检查极端高值（TOP 5 最高金额）
SELECT * FROM orders ORDER BY amount DESC LIMIT 5;
-- ④ 查找金额在0到1元之间的可疑订单（可能为测试订单）
SELECT * FROM orders WHERE amount > 0 AND amount < 1;
```

**题目3：“查询姓名包含‘明’字的员工”**

```sql

```
### 3.2 基础查询的“避坑指南”

|问题|错误写法|正确写法|
|---|---|---|
|查找空值|`WHERE email = NULL`|`WHERE email IS NULL`|
|查找不等于某个值（含NULL）|`WHERE city != '北京'`|`WHERE city != '北京' OR city IS NULL`（如果需要保留NULL，须主动处理）|
|字符串比较|`WHERE name = '张三'`（但数据中有空格）|`WHERE TRIM(name) = '张三'` 或 `WHERE name LIKE '张三'`|
|字段名有空格/保留字|`SELECT order date FROM orders`|用反引号/双引号包裹：``SELECT `order date` FROM orders``|

## 四、常见误区

|误区|真相|
|---|---|
|“`SELECT *`是最方便的写法，应该经常用”|❌ 在生产环境中应尽量避免`SELECT *`——①当表结构发生变化时，依赖列序号的代码可能出错；②返回所有列会浪费网络带宽和内存，尤其当表中包含大量文本/BLOB字段时。应显式列出需要的列|
|“`NULL`就是空字符串或0”|❌ `NULL`是“未知值”，它既不是空字符串`''`也不是0。任何与`NULL`进行的算术运算（`NULL + 1`）结果都是`NULL`；任何与`NULL`的比较（`NULL = NULL`）结果是`NULL`（未知），而非TRUE|
|“`WHERE`和`HAVING`是一样的”|❌ `WHERE`在`GROUP BY`之前执行，用于过滤原始行；`HAVING`在`GROUP BY`之后执行，用于过滤分组后的结果。简单说：`WHERE`过滤“行”，`HAVING`过滤“组”|
|“`LIKE`搜索非常快”|❌ 以通配符开头的`LIKE`查询（如`LIKE '%公司'`）**无法使用索引**，会进行全表扫描。数据量大时，此类查询会非常慢，应谨慎使用或考虑全文搜索方案|
|“SQL不区分大小写，可以随便写”|❌ SQL关键字不区分大小写（`SELECT`和`select`都行），但**数据值**是否区分大小写取决于数据库的排序规则。在MySQL中，默认`LIKE`不区分大小写；在PostgreSQL中默认区分大小写|
