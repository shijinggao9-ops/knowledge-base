**定位**：这个文件回答三个问题：6层拆解法具体是哪6层？每一层拆到什么颗粒度才算合格？不同底层驱动的游戏，在6层中各有何侧重点？理解这些，你就能确保每一篇拆解报告都结构统一、可对比、可积累。

**适用场景**：开始拆解任何一款游戏前的“开机检查清单”、确保多款游戏的拆解报告之间具有可比性、为团队其他成员提供统一的拆解标准、判断一篇拆解报告是否“到位”。


## 一、核心概念词典


### 1.1 什么是“拆解维度标准SOP”？

**拆解维度标准SOP**是一套统一的观察框架——它规定了从哪6个层面去审视一款游戏，确保每一篇拆解报告都覆盖相同的维度，从而让“全体系”真正可积累、可对比。

**为什么需要标准化？**

| 没有SOP的问题 | 有SOP的收益 |
|:--------------|:------------|
| 每款游戏拆解结构不同，无法横向对比 | 同维度对比，差异一目了然 |
| 凭感觉决定“写多少”，质量参差不齐 | 每层都有“合格线”，质量有下限保障 |
| 拆解全凭灵感，容易遗漏关键信息 | 6层清单式检查，不遗漏核心维度 |
| 跨游戏找规律要靠“印象”，难以系统化 | 数据化积累，规律自然浮现 |

### 1.2 六大拆解维度总览

|   层级    | 名称         | 核心问题                       | 时间颗粒度 | 分析重心               |
| :-----: | :--------- | :------------------------- | :---: | :----------------- |
| **第1层** | 核心循环（分钟级）  | 玩家每分每秒在做什么？爽感从哪里来？         | 秒/分钟  | 即时反馈、操作手感、战斗节奏     |
| **第2层** | 成长循环（天/周级） | 玩家每天/每周上线干什么？为什么明天还来？      |  天/周  | 日常设计、长线目标、资源循环     |
| **第3层** | 商业化设计      | 游戏怎么赚钱？付费点设计背后的心理账户是什么？    |   —   | 付费触点、付费深度、付费与体验的关系 |
| **第4层** | 社交结构       | 玩家之间是什么关系？游戏如何组织玩家群体？      |   —   | 社交层级、组队机制、社群生态     |
| **第5层** | 长线留存机制     | 玩了一个月之后，玩家为什么不走？           |  月/年  | 赛季制、内容更新、社交绑定      |
| **第6层** | 美术/UI/信息传达 | 信息如何在0.5秒内传达给玩家？审美如何服务于体验？ |   —   | UI效率、视觉引导、调性统一     |

**重要说明**：6层之间有逻辑递进关系——第1层（核心循环）是基础，没有好的分钟级体验，后面的所有设计都是空中楼阁。拆解时建议**按顺序从第1层开始**，但输出报告时可以按需调整顺序。


### 1.3 第1层：核心循环（分钟级）

**定义**：玩家在游戏中最基本的“操作-反馈-决策”单元——这是游戏“好不好玩”的最底层保障。

**核心问题清单**：

| 问题 | 拆解方法 | 合格输出示例 |
|:-----|:---------|:-------------|
| 玩家的“最小行动单元”是什么？ | 记录从“操作发生”到“反馈出现”的完整链条 | 《王者荣耀》：瞄准→释放技能→命中/未命中→伤害数字/控制效果→对手反应 |
| 一次完整循环的时长是多久？ | 计时：从开始操作到获得结果反馈 | 《只狼》：一次拼刀循环约0.5-2秒；《梦幻西游》：一个回合约15-30秒 |
| 循环中的“决策点”在哪里？ | 识别玩家需要在哪些时刻做出选择 | 《三国志·战略版》：战前配将是主要决策点，战中决策空间极小 |
| 循环中是否存在“最优解”？ | 判断：是“唯一答案”还是“多种路径”？ | 如果存在唯一最优解，游戏很快会变得无聊 |
| 失败时的反馈是什么？ | 观察“失败”的呈现方式：是惩罚、鼓励还是中性？ | 《只狼》失败有“死”字大屏 + 重生；《原神》失败只是“重来” |
| 循环是否包含“随机性”？ | 识别随机元素（暴击、掉率、发牌）及其对决策的影响 | 《金铲铲之战》的共享卡池随机是核心乐趣来源 |

**不同驱动类型在第1层的侧重点**：

| 驱动类型  | 第1层拆解重点                           |
| :---- | :-------------------------------- |
| 数值策略型 | 决策点的数量和深度、随机性与策略性的配比、是否存在“唯一最优解”  |
| 操作心流型 | 操作到反馈的延迟（帧数）、手感细节（前摇/后摇/硬直）、操作容错率 |
| 内容叙事型 | 叙事与操作的穿插节奏、探索的驱动力设计、剧情选择的反馈       |
| 社交经济型 | 单人行为与多人行为的比例、社交行为是否在核心循环中“强制出现”   |

**合格线**：能清晰描述一个“最小循环”的完整链条，包括操作类型、反馈形式、决策节点、耗时，并能指出该循环的“爽感来源”和“潜在疲劳点”。


### 1.4 第2层：成长循环（天/周级）

**定义**：玩家在更大的时间尺度上的行为模式——游戏如何通过“目标-行为-奖励”的闭环让玩家持续返回游戏。

**核心问题清单**：

| 问题 | 拆解方法 | 合格输出示例 |
|:-----|:---------|:-------------|
| 每日必做（Daily）是什么？ | 列出所有“每天上线必须/应该做的事”，按耗时排序 | 《原神》日常：4个委托+消耗体力（约15-20分钟） |
| 每周目标（Weekly）是什么？ | 列出所有“以周为单位”的目标和奖励 | 《原神》周本、声望任务、深渊重置 |
| 资源循环如何闭环？ | 画出“产出-消耗-转化”的完整路径 | 体力→副本→材料→角色升级→解锁新副本（正向循环） |
| 是否存在“断档期”？ | 识别玩家“不知道干什么”的窗口期 | 内容消耗完后、版本末期的长草期 |
| 长线目标是什么？ | 玩家在3个月/6个月/1年维度上的追求是什么？ | “满命角色”“全图鉴”“全成就”“巅峰段位” |
| 目标是否被清晰传达？ | 游戏是否明确告诉玩家“下一步该干什么”？ | 任务引导、推荐目标、成就系统的提示 |

**不同驱动类型在第2层的侧重点**：

| 驱动类型  | 第2层拆解重点                               |
| :---- | :------------------------------------ |
| 数值策略型 | 资源循环的“卡点”设计、体力/次数的限制如何调控成长速度、长线“毕业”路径 |
| 操作心流型 | 日常任务是否侵蚀核心体验（操作被日常稀释）、段位/排位作为长线目标的驱动力 |
| 内容叙事型 | 新内容推送节奏（版本更新周期）、内容消耗速度与生产速度的匹配度       |
| 社交经济型 | 团队/公会目标如何替代个人目标、社交压力如何驱动日常活跃          |

**合格线**：能画出一张“玩家一周行为时间轴”，标注每日/每周的活动分布、耗时和驱动力来源，并指出哪些行为是“我想玩”，哪些是“我必须玩”。


### 1.5 第3层：商业化设计

**定义**：游戏如何将玩家体验转化为收入——付费点的设计逻辑、付费深度、以及付费对游戏体验的影响。

**核心问题清单**：

| 问题 | 拆解方法 | 合格输出示例 |
|:-----|:---------|:-------------|
| 核心付费点是什么？ | 识别最主要的付费入口和付费形式 | 抽卡/皮肤/通行证/战力直购/订阅 |
| 付费对应的“心理账户”是什么？ | 玩家为“什么感觉”付费？（变强/变美/省时间/社交展示） | 皮肤→“社交展示”；体力→“省时间” |
| 付费深度如何？ | 计算“满氪”与“零氪”之间的差距 | 《原神》满命+精5 vs 零命+精1：伤害差距约3-5倍 |
| 付费与核心循环的关系？ | 付费是否绕过核心循环？还是加速核心循环？ | 加速体力恢复→加速循环；直购装备→绕过循环（危险信号） |
| 是否存在“诱导性付费”？ | 识别限时、首充双倍、概率展示等心理技巧 | 首充6元送强力角色（沉没成本诱导） |
| 大R（鲸鱼玩家）的付费出口在哪里？ | 头部付费玩家持续花钱的动力是什么？ | 限量皮肤、排行榜竞争、专属社交身份 |

**不同驱动类型在第3层的侧重点**：

| 驱动类型  | 第3层拆解重点                                 |
| :---- | :-------------------------------------- |
| 数值策略型 | 付费是否“卖数值”？数值型付费对游戏平衡的破坏程度、小R/中R/大R的分层设计 |
| 操作心流型 | 付费是否影响操作公平性？皮肤是否有“手感差异”（付费是否变相卖数值）      |
| 内容叙事型 | 付费是否围绕角色/故事展开？角色塑造如何驱动抽卡冲动？             |
| 社交经济型 | 付费是否展示社交身份？付费是否在社交中产生“可见的优越感”？          |

**合格线**：能清晰描述游戏的主要付费路径、各付费档位的设计逻辑、付费玩家与免费玩家的体验差异，并能评价“这个商业化设计是否在透支游戏的长线健康”。


### 1.6 第4层：社交结构

**定义**：游戏如何组织和定义玩家之间的关系——从“独自玩”到“一起玩”的阶梯设计。

**核心问题清单**：

| 问题 | 拆解方法 | 合格输出示例 |
|:-----|:---------|:-------------|
| 社交的“最小单元”是什么？ | 玩家之间最基本的互动形式 | 点赞/送体力/组队/聊天/交易 |
| 社交是“必须”还是“可选”？ | 核心内容是否需要组队完成？ | 《魔兽世界》团本=强制社交；《原神》联机=可选社交 |
| 社交层级如何设计？ | 识别“单人→小队→公会→阵营”的阶梯 | 《EVE》有完整的“单人→小队→军团→联盟→势力”五级结构 |
| 社交关系如何被“固化”？ | 是否有好友系统、公会系统、结婚/师徒等关系绑定 | 师徒系统→固化“指导-被指导”关系 |
| 社交是否有“可见的回报”？ | 社交行为是否有明确激励（还是纯情感驱动） | 组队加成、公会奖励、社交任务 |
| 负面社交如何处理？ | 游戏如何处理PVP、恶意竞争、霸凌？ | 举报系统、阵营平衡、安全区设计 |

**不同驱动类型在第4层的侧重点**：

| 驱动类型  | 第4层拆解重点                                      |
| :---- | :------------------------------------------- |
| 数值策略型 | 社交是否服务于数值成长（如公会Buff、组队加成）、社交中的资源分配机制（DKP/G团） |
| 操作心流型 | 组队时操作如何协同（技能配合/位置分工）、竞技类游戏中的团队沟通需求           |
| 内容叙事型 | 社交是否服务于“共同体验”（一起看剧情/一起探索）、社交如何强化沉浸感          |
| 社交经济型 | **此为第4层核心战场**——详细拆解公会/联盟结构、社交分层、权力博弈机制       |

**合格线**：能画出游戏的“社交金字塔”层级图，标注每层的人数规模、互动方式、奖励机制和强制程度，并指出“玩家从单人玩到多人玩的转化路径”。


### 1.7 第5层：长线留存机制

**定义**：游戏如何让玩家在“玩了一个月之后”仍然愿意留下来——这是“爆款”与“长寿”的分水岭。

**核心问题清单**：

| 问题 | 拆解方法 | 合格输出示例 |
|:-----|:---------|:-------------|
| 内容更新节奏如何？ | 版本更新的频率、每次更新的内容量、预告与上线的节奏 | 《原神》6周一个大版本，中间有角色预告、前瞻直播 |
| 是否有“回归机制”？ | 流失玩家回流的动力是什么？ | 回归奖励、追赶机制、老友召回 |
| 社交绑定是否形成“退出成本”？ | 玩家离开时，失去的社交关系是什么？ | 公会/战队的归属感、师徒关系、固定队 |
| 是否有“赛季制”或“重置机制”？ | 玩家是否定期“从头开始”以获得新鲜感？ | 段位重置、赛季通行证、新服务器 |
| 是否有“终局内容”？ | 玩家消耗完所有主线内容后，还有事可做吗？ | 高难副本、排行榜、成就收集、PvP |
| 玩家的“第30天”和“第300天”目标分别是什么？ | 长线目标的分阶段设计 | 30天：通关主线；300天：全角色毕业 |

**不同驱动类型在第5层的侧重点**：

| 驱动类型  | 第5层拆解重点                                     |
| :---- | :------------------------------------------ |
| 数值策略型 | 版本更新如何引入新数值维度（新装备/新角色）、旧数值是否被“淘汰”或“保值”      |
| 操作心流型 | 新角色/新武器如何拓展操作空间、竞技环境如何保持新鲜感（平衡调整/新英雄）       |
| 内容叙事型 | 内容生产速度能否跟上消耗速度、剧情是否持续吸引玩家                   |
| 社交经济型 | 玩家组织的“自生命力”——即使官方不更新，玩家社群能否自行产生内容（战争/交易/故事） |

**合格线**：能指出游戏“第30天留存”和“第180天留存”的核心驱动力分别是什么，并评价该游戏的长线运营策略是否可持续。


### 1.8 第6层：美术/UI/信息传达

**定义**：视觉和界面设计如何服务于“让玩家看懂、融入、不疲倦”——这是最容易被低估但最能区分“专业”与“业余”的维度。

**核心问题清单**：

| 问题 | 拆解方法 | 合格输出示例 |
|:-----|:---------|:-------------|
| 关键信息是否在0.5秒内传达？ | 模拟“第一眼看到屏幕”：最重要的信息是否第一时间被捕捉？ | 低血量时屏幕闪烁/震动（《王者荣耀》）、敌人攻击前摇的视觉提示（《只狼》） |
| UI的操作效率如何？ | 从“想做某件事”到“完成某件事”需要几步？ | 《原神》的快捷队伍切换：2步；某些MMO的功能入口深达5层菜单 |
| 审美是否服务于调性？ | 美术风格是否强化了世界观和情感体验？ | 《重返未来1999》的复古胶片UI强化了“神秘学+英伦”调性 |
| 是否存在“信息过载”？ | 界面上是否堆叠了过多信息，导致玩家疲劳？ | 国产MMO常见的“红点地狱” |
| 视觉引导是否清晰？ | 玩家是否被视觉元素“自然地引导”向关键目标？ | 亮度/色彩/动效引导视线到“可交互”元素 |
| 不同驱动类型的UI侧重点有何不同？ | 识别UI如何服务于底层驱动 | 数值型需要清晰的数据展示；操作型需要极简、不遮挡视野 |

**不同驱动类型在第6层的侧重点**：

| 驱动类型 | 第6层拆解重点 |
|:---------|:--------------|
| 🧮 数值策略型 | 数值展示是否清晰易懂（面板、词条、增益/减益的视觉表达）|
| 🎮 操作心流型 | HUD是否干扰视野、操作键位是否“顺手”、技能冷却的视觉提示是否一目了然 |
| 📖 内容叙事型 | 审美调性是否贯穿所有界面、UI交互是否服务于沉浸感（而非“跳出来”提醒玩家这是游戏）|
| 🌐 社交经济型 | 社交信息是否显眼（好友在线状态、公会通知）、排行榜/身份标识是否被突出展示 |

**合格线**：能指出UI中至少3处“优秀设计”和3处“可改进设计”，并能说明审美如何服务于（或背离于）游戏的底层驱动和核心体验。


### 1.9 不同驱动类型的维度权重分配

不是每款游戏在6层上都要“平均用力”。拆解时，建议根据底层驱动分配分析比重：

| 驱动类型 | 第1层 核心循环 | 第2层 成长循环 | 第3层 商业化 | 第4层 社交结构 | 第5层 长线留存 | 第6层 UI/信息 |
|:---------|:-----------:|:-----------:|:---------:|:-----------:|:-----------:|:-----------:|
| 🧮 数值策略型 | ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| 🎮 操作心流型 | ⭐⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐ | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |
| 📖 内容叙事型 | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 🌐 社交经济型 | ⭐⭐ | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐ |

**使用说明**：5星维度建议占拆解报告总篇幅的40%-50%；3星维度占20%-30%；2星维度一笔带过，只需回答核心问题即可。


## 二、商业场景还原


### 场景1：开始拆解一款新游戏前的“开机检查”

**背景**：你准备拆解《金铲铲之战》，打开游戏前需要先做“框架准备”。

**操作流程**：

| 步骤 | 操作 | 产出 |
|:-----|:-----|:-----|
| 第1步 | 查阅底层驱动分类，确认《金铲铲之战》属于“🧮 数值策略型（概率博弈变体）” | 明确拆解重心在第1层（核心循环）、第2层（成长循环）、第3层（商业化） |
| 第2步 | 对照权重表，确认各维度侧重点 | 第1层重点拆“共享卡池”+“发牌概率”；第3层重点拆“小小英雄/棋盘皮肤”vs“赛季通行证” |
| 第3步 | 打开游戏，按6层顺序逐一采集信息 | 用截图/录屏/笔记工具记录每层的关键观察 |
| 第4步 | 填写[[90-2-1-4 【模板】单款游戏深度拆解卡片]] | 产出标准化的拆解报告 |


### 场景2：横向对比时如何保证可比性

**背景**：你已经拆解了5款游戏，现在要做跨品类对比。

**正确做法**：

| 对比维度 | 对比方法 | 示例 |
|:---------|:---------|:-----|
| 按同一层对比 | 只拿“第3层商业化”进行多游戏对比 | 《原神》卖角色 vs《王者》卖皮肤 vs《梦幻》卖数值 |
| 在同一驱动类型内对比 | 都是操作心流型：《只狼》vs《英雄联盟》vs《王者荣耀》 | 对比三者第1层（核心循环）的“操作到反馈”链条有何不同 |
| 在同一时间节点对比 | 都是“上线第30天”的玩家体验 | 第30天时，《原神》玩家在刷圣遗物，《梦幻》玩家在做师门 |

**错误做法**：
- ❌ 拿《只狼》的第6层（UI）和《梦幻西游》的第2层（成长循环）对比——维度不同，没有意义
- ❌ 拿《原神》上线第1个月的留存机制和《EVE》上线第5年的留存机制对比——阶段不同，可比性差


### 场景3：判断一篇拆解报告是否“合格”

**背景**：你看到别人写的一篇《王者荣耀》拆解，想判断质量如何。

**检查清单**：

| 检查项 | 合格标准 | 不合格表现 |
|:-------|:---------|:-----------|
| 6层是否完整覆盖？ | 每一层至少有一个段落或章节 | 只写了“英雄设计”和“皮肤卖得好”，遗漏了成长循环和留存机制 |
| 重点是否匹配驱动类型？ | 操作心流型应重点拆第1层 | 大篇幅写商业化，核心操作手感一笔带过 |
| 是否有具体数据支撑？ | 有帧数、时长、概率等量化数据 | 全是“打击感好”“画面精美”等形容词 |
| 是否有横向参照？ | 提到同类游戏的对比 | 孤立分析，不与其他游戏对照 |
| 是否有“弃坑拐点”分析？ | 分析了游戏在什么阶段/什么原因会让玩家流失 | 只写优点，不写问题和局限 |


## 三、面试/实战中怎么用

### 3.1 面试中的SOP展示

面试官问“你怎么拆解一款游戏”时，直接展示这套6层框架是极佳的回答结构：

| 步骤 | 示例话术 | 展示的能力 |
|:-----|:---------|:-----------|
| 先分类 | “首先我会判断这款游戏的底层驱动类型……” | 有方法论（90-2-1-2） |
| 再套框架 | “然后我会用6层拆解法，从核心循环开始逐层分析……” | 有标准化SOP |
| 说重点 | “因为这款游戏是操作心流型，我会把60%的篇幅放在第1层（核心循环）……” | 懂得分配精力，不平均用力 |
| 示案例 | “比如在拆第1层时，我会记录从操作到反馈的帧数……” | 有具体实操经验 |


### 3.2 实战中的SOP使用

| 场景 | 使用方式 |
|:-----|:---------|
| 准备拆解一款游戏 | 打开本文件，按6层顺序逐一采集信息，每层回答核心问题清单 |
| 完成拆解后自检 | 对照检查清单，确保每层至少有一个合格段落，重点维度有足够深度 |
| 团队协同拆解 | 多人分工时，按6层切分任务，最后汇总整合 |
| 更新已完成的拆解 | 游戏版本更新后，只更新受影响的层（如新版本新增付费点→更新第3层）|


## 四、常见误区

| 误区 | 真相 |
|:-----|:-----|
| “拆解就是要面面俱到，每层都写一样多” | ❌ 按驱动类型分配权重。数值型重点拆第2/3层，操作型重点拆第1层，平均用力=没有重点 |
| “6层拆完就结束了” | ❌ 拆解只是第一步。拆完后要做“横向穿刺”——把不同游戏的同一层拿出来对比（见90-2-1-19至22号专题）|
| “UI层不重要，随便写写就行” | ❌ UI/信息传达是“最后一公里”——设计再好，玩家看不懂/用不顺，一切归零。尤其是操作心流型，UI劣质会直接毁掉手感 |
| “第5层（长线留存）是大厂才需要考虑的事” | ❌ 独立游戏也需要长线留存——只不过驱动不同。单机游戏的“二周目”“多结局”就是留存设计 |
| “SOP是死的，必须严格遵守” | ❌ SOP是“基准线”而非“枷锁”。遇到特殊游戏（如纯单机线性叙事），可以合并/跳过某些层，但需要有明确理由 |
